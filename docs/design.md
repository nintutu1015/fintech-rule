# 设计约定

## 三类数据

1. **自己的决定**：本地规则、应用分组、地区选择和兜底，进入版本管理。
2. **上游来源**：在 `config/upstreams.json` 保存 URL、策略和顺序。顺序有语义，不按字母自动排序。
3. **私人连接资料**：只在 `.local/private.json`。构建结果只写入 `dist/`；这两个目录都被 Git 忽略。

模板使用七个明确占位符，构建器只替换一遍，不执行模板代码或远程脚本。公开检查使用符号节点名，不需要访问真实节点。

## 本次迁移保留的行为

- 采用此前确认的 DNS、MESL 参数和测速方式。
- 保留 A 原有的规则相对优先级；Grok 指向 AI，PayPal 规则先于通用 Global。
- 原“漏网之鱼”的规则、插件和 FINAL 都已统一到 Proxy。
- 保留现有地区筛选正则，不根据机场名称猜测新的地区。
- 本地 CN 直连、三条缺策略 IP 和天气插件启用状态按原选择保留。

改变这些行为时，在同一次修改中更新说明与回归预期；不把“整理文件”当作更改出口的理由。

## 检查能说明什么

`check` 能检查目前支持的本地规则形式、策略引用、循环、重复命名、同条件不同策略、FINAL、菜单与关键规则顺序。凭据扫描是启发式的，同时检查强行跟踪了忽略目录的情况，不能代替对发布 diff 的审阅。

`tests/expectations.json` 保存用户意图，例如 PayPal 在 Global 之前、AI 菜单能选自建节点、Proxy 是全部节点入口。

当前不会下载远程规则，不能断言远程规则没有重叠；也不模拟 GEOIP、全部逻辑规则、脚本和 Mitm 行为。构建成功不等于设备上连接可用。

## GitHub 上线

先确定账号、仓库名、公开范围。公开规则仓库方便 Loon 读取无需认证的资源；私有仓库需另外确定认证或分发路径，不把 GitHub 访问令牌写进公开 URL。

后续可添加按服务发布的单策略规则文件。把本地片段变成远程订阅会降低规则来源优先级，必须单独审查，不能仅替换文件地址。

固定提交的链接适合冻结版本；分支链接会随提交变化。先使用手动检查和发布，再根据实际需要决定是否自动跟踪上游。
